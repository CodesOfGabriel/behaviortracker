CFF is checked against the official 1.2.0 schema. Zenodo JSON core fields are

consistency. No DOI, release date, funding or copyright owner is invented.

Both Wistar payloads and both pinned CoTracker assets passed full remote
size/SHA-256 streaming checks. No downloaded third-party code was executed as
part of those integrity checks. This proves retrieval/integrity at review time,
not permission to redistribute or permanent archival preservation.

The tracked text scan checked private-key blocks, common GitHub/AWS/Google/Slack
token forms and credential-bearing URLs, plus sensitive file types and
notebook outputs. No matching secret or tracked private credential file was
found. Pattern scanning is bounded; study-derived images and diagnostics need
their own review. A personal absolute path in the RAM contract was replaced by
a generic reference; no experimental source data were copied into the repo.

## Historical distribution findings

The [distribution inventory](distribution-audit.json) records public release
metadata and declared installer resources. Direct, non-executing archive
inspection covered the Linux `.deb` files for 0.1.4 and 0.1.6.

- The public `models-wistar-df-v2-r1` release distributes both Wistar weights.
- The 0.1.4 Linux installer contains both Wistar checkpoint files. Their sizes
  and hashes are compared with the current delivery manifest in the inventory.
- The 0.1.6 Linux installer contains no standalone `.pth`, `.pt` or `.onnx`
  file; it contains application icons and a video-tools license notice.
- Application web assets may be embedded in the native executable rather than
  separate files. Filename references alone do not prove exact media payload
  identity. Earlier-platform installer configurations and API sizes provide
  evidence of packaging choices, not a complete unpacking of every installer.

Windows/macOS/AppImage payloads and the older Linux payloads were not all
unpacked. No published asset was removed or replaced. Existing distribution
of potentially SuperAnimal-derived weights requires a rights/provenance
decision; integrity checks cannot resolve that issue.

## Remaining review before publication

Trace the current custom checkpoint hashes to their upstream initialization,
adaptation/training history and data rights. Confirm experimental-video and
derived-data redistribution authority. Preserve the applicable terms of
SuperAnimal, CoTracker and pretrained initialization; do not assign them the
code's Apache license. Address the FST immutable-weight and complete Python
environment gaps, and the source/notice arrangements for each binary
dependency actually conveyed. The modular provider approach proposed in
`MODEL_CARD.md` keeps official-source acquisition and user training distinct
from the authorial application code; it is not silently implemented here.

For a future JOSS submission, consult the
[current submission requirements](https://joss.readthedocs.io/en/latest/submitting.html)
and [review criteria](https://joss.readthedocs.io/en/latest/review_criteria.html).
They require an open-source license, usable documentation/tests, evidence of
research impact and sustained public development, and disclosure of AI use.
A Zenodo DOI alone does not establish JOSS eligibility or scientific accuracy.
No paper, external adoption or review outcome has been invented.

The maintainer's final release approval remains required. This review is not
an instruction to publish or to change existing public releases.
